# REVIEW.md

| # | Where | What is wrong | How to notice | Fix |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses naive replacement and integer minutes without the strict 10-minute boundary semantics being explicit; timezone handling is unsafe. | 09:40:01 for a 09:30 shift must report 10 late minutes. | Normalize instants to UTC/IST and compare elapsed seconds; only mark late when elapsed seconds are strictly greater than 600. |
| 2 | `compute_overtime` | Builds a shift-end timestamp on the same date even for overnight shifts and counts any positive overtime. | 22:00–06:00 shift punched out at 06:20 should not get overtime; at 06:30 it should. | Resolve the shift-end calendar day for overnight shifts and apply the 30-minute threshold. |
| 3 | `compute_work_hours` | Python `round`/binary float behavior can use banker's rounding rather than required half-up rounding. | Test a duration exactly halfway between hundredths. | Use `Decimal` with `ROUND_HALF_UP`. |
| 4 | `create_employee` | Check-then-insert is racy and has no validation that shift start differs from shift end. | Send simultaneous requests with the same `emp_code`; or create equal shift times. | Enforce a unique database index and translate `DuplicateKeyError` to 409; validate shift values. |
| 5 | `list_employees` | `skip=page * page_size` skips page 1, and `total` ignores the department filter. Results are not sorted. | Page 1 omits the first page; filtered total differs from result count. | Use `(page-1)*page_size`, count the same filter, sort by `emp_code`, and constrain page size. |
| 6 | `punch_in` | Missing employee causes a 500; seconds/local timezone are ambiguous; only a preflight duplicate check is used; timestamp types/range and status are not validated. | Unknown code, epoch seconds, concurrent duplicate requests, or a fractional-second timestamp. | Return 404, validate epoch milliseconds, truncate to seconds, calculate IST attendance date, accept only presence statuses, and rely on a unique `(emp_code,date)` index for race safety. |
| 7 | `punch_in` | Derived late minutes can be wrong at the grace boundary and stored instants use local-naive time. | Test 09:40:00 and 09:40:01 for a 09:30 shift. | Use UTC-aware instants and the explicit R2 rule. |
| 8 | `list_attendance` | Reads the entire collection, sorts in Python, paginates after loading, and does not validate date order/status. | Performance and memory degrade at 100k records; `date_from > date_to` is accepted. | Count filtered records, query with indexed filters/sort, and apply skip/limit in MongoDB. |
| 9 | `list_attendance` | Response leaks MongoDB `_id` and omits the required stable response convention for instants. | Inspect raw response JSON. | Strip `_id` and serialize all BSON instants as epoch milliseconds. |
| 10 | Missing punch-out endpoint | No atomic close operation or validation for missing/already-closed records, elapsed time, overnight shifts, or derived fields. | Parallel punch-outs or a punch-out more than 24 hours later. | Find the latest eligible record and conditionally update only while `punch_out` is null. |
| 11 | Missing regularization endpoint | No change validation, derived-field recomputation, or append-only audit history. | Correct a status/time and inspect history. | Recompute derived values, store only actual changes, append one history item, and use optimistic compare-and-swap to avoid lost updates. |
| 12 | Missing analytics endpoints | Monthly/department/leaderboard/trend analytics were unimplemented. | Requests return 404. | Add MongoDB aggregation pipelines, including rank-with-ties and gap filling for daily trend. |
| 13 | Missing explain endpoint/indexes | No query-plan endpoint and no startup indexes. | Explain cannot run; queries may use collection scans. | Create indexes idempotently and return `executionStats` explain output for supported query shapes. |

**Reviewed and retained:** `MONGO_URI` and `MONGO_DB` are configurable, and the natural attendance key is `(emp_code, date)`. The revised implementation keeps both conventions, while adding database-enforced uniqueness and health-check readiness.
